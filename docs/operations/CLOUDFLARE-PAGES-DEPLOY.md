# Deploying davetim.app on Cloudflare Pages

The domain has to serve **one site built from two apps**, because the mobile
client hard-codes `https://davetim.app` in every link it hands a guest.

| Path | Comes from |
|---|---|
| `/`, `/privacy`, `/terms`, `/support`, `/account-deletion` | `apps/landing` |
| `/app-ads.txt` | `apps/landing/public` |
| `/i/*`, `/rsvp/*`, `/media/*` | `apps/mobile` Expo web export |

`scripts/build-web.sh` produces that merged site in `dist-web/`. Only the three
guest-facing route families are taken from the mobile export — the editor,
invitation list and account screens are behind a sign-in and have no reason to
be reachable on the web.

## What is already done

- `npm run build:web` at the repository root builds and merges both apps.
- `_redirects` and `_headers` are generated by the script, so they cannot drift
  from the routing they describe.
- Verified locally against a Cloudflare-Pages-shaped emulator (static files
  first, then `_redirects` in order): all eight required paths answer 200,
  `/app-ads.txt` is served as `text/plain`, a real published invitation renders
  from Supabase at `/i/<id>`, and `/privacy` renders the legal page rather than
  the home page.
- `dist-web/` and the intermediate export are gitignored.

## Steps for you

### 1. Create the Pages project

Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git, and
pick this repository.

Build settings:

| Field | Value |
|---|---|
| Framework preset | None |
| Build command | `npm run build:web` |
| Build output directory | `dist-web` |
| Root directory | *(leave empty — the script expects the repo root)* |

### 2. Build environment variables

Set these for **Production** (and Preview, if you use it). The mobile export is
built during deployment, so its public env vars have to exist in Cloudflare, not
only in your local `.env`:

```
EXPO_PUBLIC_SUPABASE_URL              https://lwowqdxysoqrwoylhouy.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY  sb_publishable_…
EXPO_PUBLIC_PUBLIC_APP_URL            https://davetim.app
EXPO_PUBLIC_ENABLE_BACKEND_WRITES     true
NODE_VERSION                          22
```

Only the publishable key belongs here. The secret key bypasses RLS and must
never reach a build that produces browser JavaScript.

`EXPO_PUBLIC_ENABLE_REWARDED_ADS` is not needed: the build script forces it off,
because ads are native-only and leaving it on would make `app.config.ts` demand
AdMob IDs for a build that can never show an ad.

### 3. Point the domain at Pages

Custom domains → add `davetim.app` and `www.davetim.app`.

**The domain currently resolves to a website builder** (`server: hcdn`) — that
is what is serving the placeholder page today. Removing or repointing the
existing DNS record is the step that actually fixes the dead invitation links,
so do it deliberately rather than adding a record alongside the old one.

If the zone is already on Cloudflare, the custom-domain flow rewrites the record
for you; if it is elsewhere, move the nameservers first.

### 4. Verify before you announce anything

```bash
for p in / /privacy /terms /support /account-deletion /app-ads.txt; do
  curl -sS -o /dev/null -w "%{http_code} %{content_type}  $p\n" "https://davetim.app$p"
done
```

Then open a real shared link — publish an invitation in the app, tap **Paylaş**,
and open the URL on a device that is not signed in. That is the one path that
matters most and the one that has been broken.

`/app-ads.txt` must come back as `text/plain`. If it returns HTML, the SPA
catch-all is winning and AdMob will not read it.

### 5. After the domain is live

- AdMob picks up `app-ads.txt` on its own crawl schedule; the status in the
  AdMob console can take a day or two to turn green.
- Put the `/privacy` and `/support` URLs into App Store Connect.
- The store badges on the landing page read `VITE_APP_STORE_URL` and
  `VITE_PLAY_STORE_URL`; set them once the listings exist, and leave them unset
  until then so the badges stay disabled.

## Rebuilds

The mobile export is rebuilt on every deployment, so a change to a guest-facing
screen ships with the next push. Nothing needs to be exported by hand.
